Distribucion de tablas de inventario

====================================================
A) INVENTARIO PC
====================================================

1. Tabla principal: equipos
- id_equipo
- id_usuario (usuario que creo el registro — campo original, se mantiene)
- id_colegio (inmutable: no se puede cambiar desde el formulario)
- id_ubicacion (nullable, FK logica -> equipo_ubicacion.id_ubicacion — requiere migracion: migracion_add_equipos_id_ubicacion.sql)
- id_usuario_asignado
- id_usuario_registra (nullable, usuario de sesion que registra el equipo — requiere migracion: migracion_add_equipos_id_usuario_registra.sql)
- nombre_equipo (obligatorio)
- fabricante
- producto
- numero_serie (obligatorio, unico)
- tipo_pc (VARCHAR, valor textual del catalogo tipo_pc_catalogo — obligatorio)
- qr_code
- id_estado (obligatorio, estado operativo; cambiar a Baja NO elimina el equipo)
- eliminado (TINYINT, 0 = visible, 1 = eliminado logicamente; requiere migracion: migracion_add_equipos_eliminado.sql)
- fecha_eliminado (nullable, auditoria de eliminacion logica)
- id_usuario_elimina (nullable, usuario que marco eliminado = 1)

Reglas de eliminacion logica:
- equipos.eliminado = 0 → equipo visible en listados y KPIs.
- equipos.eliminado = 1 → equipo eliminado logicamente, no aparece.
- El boton basurero marca eliminado = 1. NO cambia id_estado.
- El basurero no borra registros fisicos de la tabla equipos.
- El cambio de estado operativo (Activo, Baja, Bodega...) se realiza desde el badge de estado.

2. Tabla relacionada: equipos_compra
- id_equipo
- valor_equipo
- proveedor
- numero_factura
- fecha_compra
- observacion

3. Tabla relacionada: equipo_almacenamiento
- id_equipo
- equipo_modelo
- equipo_capacidad
- equipo_tamano

4. Tabla relacionada: equipo_memoria
- id_memoria
- id_equipo
- designacion_memoria
- formato_memoria
- tipo_memoria
- tamano_memoria
- frecuencia_memoria
- marca_memoria
- orden_memoria

5. Tabla relacionada: equipo_monitor
PROPOSITO: Monitores fisicamente asociados a un PC especifico.
NO confundir con la tabla "monitores" (modulo independiente de monitores).
Gestionada desde el formulario de PC (seccion "Monitores asociados al PC").
- id_monitor (PK autoincremental)
- id_equipo (FK -> equipos)
- modelo_monitor
- codigo_monitor
- serie_monitor
- tamano_monitor
- resolucion_monitor
- orden_monitor

DIFERENCIA CRITICA:
  equipo_monitor  = monitor vinculado a un PC (este modulo, legacy, no eliminar).
  monitores       = monitor independiente (pestana Monitores, modulo separado).

6. Tabla relacionada: equipo_procesador
- id_equipo
- equipo_fabricante
- equipo_modelo
- equipo_velocidad

7. Tabla relacionada: equipo_software
- id_equipo
- windows
- office
- antivirus

8. Tabla relacionada: equipo_fotos
Objetivo:
- Guarda las imagenes asociadas a cada equipo.
- Permite varias fotos por equipo.
- Una foto puede marcarse como principal usando principal = 1.
- El campo tipo_foto maneja los valores oficiales: normal y panoramica.

Campos:
- id_foto: clave primaria.
- id_equipo: equipo relacionado.
- ruta_foto: ruta relativa del archivo fisico.
- tipo_foto: tipo de imagen, valores oficiales 'normal' o 'panoramica'.
- principal: 1 si es la foto principal del equipo, 0 si no.
- orden_foto: orden visual en la galeria.
- fecha_subida: fecha de carga.

Relacion:
- equipo_fotos.id_equipo referencia a equipos.id_equipo (1:N).

Regla:
- Solo debe existir una foto principal por equipo.
- Antes de marcar una foto como principal, poner en 0 todas las del mismo equipo:
  UPDATE equipo_fotos SET principal = 0 WHERE id_equipo = ?
- Luego marcar la nueva:
  UPDATE equipo_fotos SET principal = 1 WHERE id_foto = ? AND id_equipo = ?

9. Tabla de historial: equipo_movimiento
Objetivo:
- Guarda el historial de cambios de ubicacion de un equipo.

Campos:
- id_movimiento: clave primaria.
- id_equipo: equipo que fue movido.
- id_ubicacion_origen: ubicacion desde donde salio (puede ser NULL si es primer registro).
- id_ubicacion_destino: ubicacion a la que llego el equipo.
- id_usuario_movimiento: usuario que registro el movimiento.
- fecha_movimiento: fecha y hora del traslado.
- motivo: razon del traslado (opcional).
- observacion: detalle adicional (opcional).

10. Tabla de historial: equipo_asignacion_historial
Objetivo:
- Registra cada cambio de usuario asignado para equipos PC.
- Incluye la liberacion (id_usuario_nuevo = NULL).
- Nunca se borra; es un log permanente.

Campos:
- id_asignacion: clave primaria autoincremental.
- id_equipo: equipo relacionado.
- id_usuario_anterior: usuario que tenia asignado el equipo antes del cambio (nullable).
- id_usuario_nuevo: usuario nuevo al que se asigna (NULL cuando se libera).
- id_usuario_accion: usuario de sesion que realizo la accion.
- fecha_accion: fecha y hora de la accion (auto, DEFAULT CURRENT_TIMESTAMP).
- motivo: descripcion corta del tipo de accion.
- observacion: detalle textual adicional (opcional).

11. Tabla de historial: equipo_estado_historial
Objetivo:
- Registra cada cambio de estado operativo de equipos PC.

Campos:
- id_historial: clave primaria autoincremental.
- id_equipo: equipo relacionado.
- id_estado_anterior: estado antes del cambio.
- id_estado_nuevo: estado nuevo.
- id_usuario_accion: usuario de sesion que realizo el cambio.
- fecha_accion: fecha y hora de la accion.
- observacion: detalle textual.

Reglas:
- Cambiar a Baja solo actualiza id_estado.
- Eliminar desde basurero solo marca eliminado = 1.
- No borrar fisicamente registros de equipos.

====================================================
B) INVENTARIO MONITORES INDEPENDIENTES
====================================================

IMPORTANTE: Este modulo es DISTINTO a la tabla equipo_monitor del modulo PC.
- equipo_monitor: monitores vinculados a un PC (formulario PC, tabla legacy).
- monitores: monitores comprados de forma independiente (pestana "Monitores", tablas nuevas).
No se migran datos entre ambas tablas. No se mezclan las logicas.

12. Tabla principal: monitores
- id_monitor: clave primaria autoincremental.
- id_colegio: colegio al que pertenece (obligatorio, inmutable desde formulario).
- id_ubicacion: ubicacion interna actual (nullable, FK logica -> equipo_ubicacion).
- id_usuario_asignado: usuario responsable del monitor (nullable).
- id_usuario_registra: usuario de sesion que creo el registro (auto desde sesion).
- id_estado: estado actual (FK logica -> estado_equipo.id_estado).
- nombre_monitor, marca, modelo, numero_serie (obligatorios).
- codigo_interno, tamano_monitor, resolucion_monitor, tipo_panel, tipo_conexion, observacion.
- fecha_registro: auto.
- eliminado: TINYINT(1) DEFAULT 0. Requiere migracion: migracion_add_monitores_eliminado.sql

Reglas de eliminacion logica:
- monitores.eliminado = 0 → monitor visible en listados y KPIs.
- monitores.eliminado = 1 → monitor eliminado logicamente, no aparece.
- El boton basurero marca eliminado = 1. NO cambia id_estado.
- El basurero no borra registros fisicos de la tabla monitores.
- El estado operativo se maneja con monitores.id_estado (igual que equipos.id_estado).

13. Tabla relacionada: monitor_fotos
- id_foto, id_monitor, ruta_foto, tipo_foto ENUM('normal','panoramica'), principal, orden_foto, fecha_subida.
- Fotos guardadas en: inventario/uploads/monitores/{id_monitor}/
- Solo una foto principal por monitor (principal = 1).

14. Tabla relacionada: monitor_movimiento
- id_movimiento, id_monitor, id_ubicacion_origen (NULL si alta inicial), id_ubicacion_destino,
  id_usuario_movimiento, fecha_movimiento, motivo, observacion.

15. Tabla relacionada: monitor_compra (1:1 con monitores)
- id_monitor (PK), valor_monitor, proveedor, numero_factura, fecha_compra, observacion.

16. Tabla de historial: monitor_asignacion_historial
- Misma estructura que equipo_asignacion_historial, pero para monitores.
- Campos: id_asignacion, id_monitor, id_usuario_anterior, id_usuario_nuevo,
  id_usuario_accion, fecha_accion, motivo, observacion.

====================================================
C) CATALOGOS COMPARTIDOS
====================================================

17. Tabla de estados: estado_equipo
Objetivo:
- Mantiene los estados disponibles para los equipos del inventario.
- Compartida entre modulo PC y modulo Monitores.
- Solo se deben mostrar los registros con estado = 1.

Campos:
- id_estado: clave primaria.
- nombre_estado: nombre visible del estado.
- color_badge: color Bootstrap usado para mostrar el badge (success, secondary, warning, danger, info, etc.).
- estado: permite activar o desactivar estados (1 = activo, 0 = inactivo).

Datos actuales:
1 | Activo     | success
2 | Bodega     | secondary
3 | Reparacion | warning
4 | Baja       | danger
5 | Prestado   | info

Relaciones:
- equipos.id_estado referencia a estado_equipo.id_estado (N:1).
- monitores.id_estado referencia a estado_equipo.id_estado (N:1).
- `id_estado` es estado operativo. Estado "Baja" NO equivale a eliminacion logica.
- Los cambios de estado se registran en equipo_estado_historial.

18. Tabla de ubicaciones: equipo_ubicacion
Objetivo:
- Guarda las ubicaciones fisicas internas disponibles por colegio.
- Compartida entre modulo PC y modulo Monitores.
- Cada colegio tiene su propio conjunto de ubicaciones.

Campos:
- id_ubicacion: clave primaria.
- id_colegio: colegio al que pertenece la ubicacion.
- nombre_ubicacion: nombre visible.
- tipo_ubicacion: categoria de la ubicacion.
- descripcion: texto descriptivo opcional.
- estado: 1 = activa, 0 = inactiva.

Ubicaciones cargadas inicialmente (por cada colegio activo):
- Sala Computacion 1 (Sala Computacion)
- Sala Computacion 2 (Sala Computacion)
- Biblioteca (Biblioteca)
- Direccion (Oficina)
- UTP (Oficina)
- Inspectoria (Oficina)
- Enfermeria (Enfermeria)
- Porteria (Porteria)
- Laboratorio Ciencias (Laboratorio)
- Bodega Informatica (Bodega)

19. Catalogo de tipos de PC: tipo_pc_catalogo
Objetivo:
- Provee los tipos de PC disponibles para el modulo de inventario PC.
- Solo se muestran los tipos con activo = 1.

Campos:
- id_tipo_pc: clave primaria autoincremental.
- nombre_tipo: nombre del tipo (Desktop, Notebook, All In One, etc.) — UNIQUE.
- activo: 1 = visible en formularios, 0 = oculto.

Datos iniciales:
Desktop, Notebook, All In One, Mini PC, Servidor, Otro

Nota:
- equipos.tipo_pc (VARCHAR) toma su valor desde tipo_pc_catalogo.nombre_tipo.
- No hay FK formal, la relacion es logica.

20. Tabla de referencia: colegio
Objetivo:
- Registro de colegios administrados por SEDUC.
- Compartida con el sistema general.

Campos relevantes para inventario:
- id_colegio: clave primaria.
- nom_colegio: nombre del colegio.
- color_principal, color_secundario, color_terciario, color_cuaternario: branding visual.

21. Tabla de referencia: usuarios
Objetivo:
- Registro de usuarios del sistema.
- Compartida con el sistema general.

Campos relevantes para inventario:
- id: clave primaria.
- nombre, apellido_paterno: nombre del usuario.

====================================================
RELACIONES GENERALES
====================================================

Modulo PC
- equipos es la tabla principal.
- equipos_compra se relaciona por id_equipo.
- equipo_almacenamiento se relaciona por id_equipo.
- equipo_memoria se relaciona por id_equipo.
- equipo_monitor se relaciona por id_equipo (LEGACY — monitores vinculados al PC; NO eliminar).
- equipo_procesador se relaciona por id_equipo.
- equipo_software se relaciona por id_equipo.
- equipo_fotos se relaciona por id_equipo.
- equipo_movimiento se relaciona por id_equipo.
- equipo_asignacion_historial se relaciona por id_equipo.
- equipo_estado_historial se relaciona por id_equipo.
- estado_equipo se relaciona con equipos por id_estado (N:1).
- equipo_ubicacion se relaciona con equipos por id_ubicacion (1:N).
- tipo_pc_catalogo provee valores logicos para equipos.tipo_pc (sin FK formal).

Modulo Monitores
- monitores es la tabla principal independiente del modulo Monitores.
- monitor_fotos, monitor_movimiento, monitor_compra se relacionan por id_monitor.
- monitor_asignacion_historial se relaciona por id_monitor.
- estado_equipo y equipo_ubicacion son compartidas con el modulo PC.
- equipo_monitor (legacy) NO pertenece a este modulo.
