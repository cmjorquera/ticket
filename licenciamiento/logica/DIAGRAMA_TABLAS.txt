3. Resumen de relaciones
------------------------
- `colegio` 1:N `software_catalogo`
- `software_catalogo` 1:N `software_datos_almacenamiento`
- `software_catalogo` 1:N `software_historial`
- `software_catalogo` 1:N `software_datos_sensibles_rel`
- `software_catalogo` 1:N `software_tipo_usuario_rel`
- `inventario_software_datos_sensibles` 1:N `software_datos_sensibles_rel`
- `inventario_software_tipo_usuario` 1:N `software_tipo_usuario_rel`
- `usuarios` 1:N `software_catalogo`
- `colegio` 1:N `sitios_web_catalogo`
- `usuarios` 1:N `sitios_web_catalogo`

4. Notas utiles
---------------
- `software_datos_sensibles_rel` es la tabla puente entre software y catalogo de datos sensibles.
- `software_tipo_usuario_rel` es la tabla puente entre software y catalogo de tipos de usuario.
- `inventario_software_tipo_usuario` funciona como catalogo de tipos de usuario del sistema.
- `software_catalogo.id_tipo_usuario` puede existir como legado, pero la asociacion multiple se resuelve con `software_tipo_usuario_rel`.
- `software_historial` guarda trazabilidad basica del ciclo de vida del software.
- `sitios_web_catalogo` es parte del mismo modulo, pero separado del flujo de licencias.
